# V0 — Minimal Agent 学习笔记

## 本版问题

Agent 和一次普通的 LLM 调用有什么区别？

答案不是“用了某个 Agent 框架”，而是模型能够提出行动，运行时执行行动，把观察结果放回对话，再让模型决定下一步。

## 一次完整循环

```text
1. 用户输入任务
2. Agent 把 system message 和 user message 发送给模型
3. 模型返回 assistant message
4. 如果 message 包含 tool_calls，Agent 根据名称找到工具
5. Tool 接收 JSON 参数并在工作区执行
6. Agent 把 tool message 追加到消息历史
7. 再次调用模型
8. 如果模型不再请求工具，得到最终回答
```

对应的核心代码在 `src/forgecode/agent_v0.py` 的 `AgentLoop.run`。

## 三个边界

### Model

模型负责根据消息和工具 Schema 产生下一步响应。它可以请求工具，但不会直接读取本地文件或运行进程。

### Runtime

Runtime 负责循环、停止条件、消息历史和 Tool Call 分发。它是 Agent 的控制器。

### Tool / Environment

Tool 负责把模型的结构化请求转换为真实环境操作，并把结果转换为模型能够理解的 Observation。

## 为什么需要 Tool Result

模型第一次只知道任务和工具说明，不知道仓库中的真实内容。Tool Result 是环境反馈。如果不把它加入下一次请求，模型就无法基于刚才读到的文件继续推理。

## 为什么需要 Fake Model

真实模型具有网络、费用和非确定性。Fake Model 可以预先返回：

```text
第一次：调用 read_file
第二次：输出最终答案
```

这样可以确定性地测试 Agent Loop，而不是测试某个模型今天是否刚好做出了正确选择。

## 当前实现的限制

- V0 只适合受控的本地学习环境；
- `run_command` 接收 argv，不支持 shell 管道和重定向；
- 还没有代码修改能力；
- 还没有 LangChain/LangGraph；
- 还没有任务持久化和恢复；
- 还没有专门的 Repository Context；
- 还没有系统性 Benchmark。

## V0 面试复述

ForgeCode V0 是一个手写的 Tool-Calling Agent Loop。模型输出中可以包含结构化 Tool Call，Agent Runtime 根据工具名和参数分发执行，再把 Tool Result 作为 tool message 追加回消息历史，模型据此决定是否继续行动。循环在模型返回无 Tool Call 的 assistant message 或达到最大步骤数时停止。测试中使用 Fake Model 回放工具调用序列，验证了工具成功、工具错误和预算终止等控制逻辑。
